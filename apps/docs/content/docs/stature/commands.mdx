Every command is under `/stature` and asks for permission level 2, the gamemaster level.
`<targets>` is any entity selector; only living entities are changed, and a selector that matches
nothing living reports `No living entities matched`. Scale changes are server-authoritative, so a
command run from the console changes the server's answer and the players tracking the entity are
sent the result.

## At a glance

```cmd
/stature set <targets> <scale>
/stature set <targets> <scale> <ticks>
/stature set <targets> <scale> <ticks> <easing>
/stature set <targets> --dangerous <scale> [<ticks> [<easing>]]
/stature set <targets> <scale> [<ticks> [<easing>]] --dangerous
/stature reset <targets>
/stature size <targets> <width> <height> <depth> [<ticks>]
/stature frame apply <targets> <frame> [<ticks>]
/stature frame clear <targets>
/stature frame list
/stature channel <targets> list
/stature channel <targets> <channel> <value>
/stature channel <targets> <channel> reset
/stature part <targets> list
/stature part <targets> reset
/stature part <targets> <part> <x> <y> <z> [<ticks>]
/stature part <targets> <part> reset
/stature get [<target>]
/stature reload
```

`<easing>` is one of `linear`, `cubic` or `elastic`. Ticks run from 0 to 1200. Without ticks the
change lands at once; with ticks and no easing name it uses `cubic`.

## Setting a size

```cmd
/stature set @s 2
/stature set @s 4 40 elastic
/stature set @e[type=minecraft:zombie,limit=1] 0.5 20 linear
```

`set` changes only the uniform scale and keeps the current shape. It marks the entity as a manual
choice, so a pack's automatic frame no longer applies to it. The plain range is 0.0625 to 16, the
range the game's `minecraft:scale` attribute stores. A value outside it is refused with a message
that names `--dangerous`.

```cmd
/stature set @s 100 --dangerous
/stature set @s --dangerous 100
/stature set @s 100 40 elastic --dangerous
```

`--dangerous` may follow the scale, the ticks or the easing, and the prefix form puts it before the
scale. It accepts 0.001 to 1000. Above 256 the command logs a warning. The box holds the nearest
bound (see [Dangerous sizes](/docs/stature/dangerous/)) and the model shows the requested size.

## Resetting

```cmd
/stature reset @s
/stature reset @e[type=minecraft:zombie]
```

`reset` returns the entity to vanilla: scale, shape, frame, channels and parts are all cleared. It
stays marked as manually decided, so a pack's automatic frame does not reapply on the next tick. It
is the one command to reach for when an entity is in a state nobody can explain.

The narrower resets are separate:

| Command | What it clears |
|---|---|
| `/stature frame clear <targets>` | The frame, the scale and the parts; channels stay, except a dangerous set's model channel |
| `/stature channel <targets> <channel> reset` | One channel override |
| `/stature part <targets> reset` | Every part factor |
| `/stature part <targets> <part> reset` | One part, or one group's parts |

## Shaping the box

```cmd
/stature size @s 0.5 1.2 2.0
/stature size @s 0.5 1.2 2.0 40
```

The three numbers are width, height and depth in blocks, each from 0.0625 to 16. The depth is
independent of the width, so `0.5 1.2 2.0` is a box that is much deeper than it is wide. `size`
keeps the current uniform scale and clears any named frame. A hand shape is a manual choice, so a
pack's automatic frame no longer applies. Ticks ease with `cubic`; there is no easing argument on
this command.

## Frames

```cmd
/stature frame apply @s mypack:titan
/stature frame apply @e[type=minecraft:zombie,limit=1] mypack:giant 40
/stature frame list
/stature frame clear @s
```

`frame apply` takes a frame id loaded from a datapack. The command completes loaded ids, and an
unknown name is refused with a message that points at `frame list`. The frame supplies its own
easing, size, parts, hurt regions and threshold overrides. Applying a frame is an explicit choice,
so later automatic assignments leave the entity alone.

`frame clear` returns the entity to vanilla proportions. Like `frame apply`, it is explicit: the
entity is marked as manually decided and a pack does not claim it again on the next tick.

`frame list` prints every loaded frame id, or says that no frames loaded and where a pack puts them.

## Channels

```cmd
/stature channel @s list
/stature channel @s stature:attack 2
/stature channel @s stature:attack reset
```

`channel` takes one channel id and one finite value. The value is deliberately unbounded: the
channel's own meaning decides what is sensible. A set value is an override and is applied at once.
`list` prints every channel's resolved value and marks the entries that are overrides with
`(override)`.

`reset` drops the override, so the channel follows the scale again, or returns to exactly 1.0 for a
channel that follows nothing. The full list of ids, defaults and effects is in
[Channels](/docs/stature/channels/).

## Parts

```cmd
/stature part @s list
/stature part @s arm.right 1 2 1
/stature part @s arm.right 1 2 1 20
/stature part @s arm.right reset
/stature part @s reset
```

`<part>` is a rig group such as `head`, `arm.left` or `all`, or a raw dot path such as
`body.left_arm`. The three numbers are per-axis multipliers from 0.0625 to 16. Ticks ease with
`cubic`.

A group resolves through the entity's rig at set time, and the resulting model paths are what
travel; a later rig change does not reinterpret a factor that is already set. A raw path passes the
command if its syntax is valid, because only the client's model knows whether the path exists; a
path that is not on the model is reported once in the client log and does nothing. `part list`
prints the factors by path, not by group name.

## Reading state

```cmd
/stature get
/stature get @e[type=minecraft:zombie,limit=1]
```

`get` reports the uniform scale and the resulting box. When there is no frame and the box is
shaped, it also reports the three multipliers. When a frame is applied, it names the frame; if the
frame file has since been removed, it says the name is no longer loaded rather than pretending the
numbers came from nowhere. Without a target, `get` reads the player who ran it.

## Reloading

```cmd
/stature reload
```

`reload` re-reads the server's `config/stature.json`, every frame and every rig, re-evaluates
automatic frame assignments, and refreshes the threshold values sent to clients. It reports how
many frames loaded and how many entities changed.

Vanilla `/reload` also reloads frames and rigs and re-evaluates automatic assignments, because
both loaders register a server data listener. It does not re-read `config/stature.json`; use
`/stature reload` for that.
